# 依頼内容
過去の気象データと直近の気象トレンドを掛け合わせて、指定した場所・日付の天気と気温を予測するWebアプリケーションを作成してください。
サーバーサイドの処理は使わず、フロントエンド（HTML / CSS / Vanilla JS または 単一ファイルのReact構成）のみで完結し、PC・スマートフォンの両方で快適に使えるレスポンシブなモダンUIとして実装してください。

---

# 1. 技術スタック・外部API仕様
すべて無料・APIキー不要のエンドポイントを使用します。

1. **フロントエンド**: HTML5, Tailwind CSS (CDN), JavaScript (ES6+), アイコン表示用に Lucide Icons または FontAwesome (CDN)
2. **ジオコーディング（場所検索）**: Nominatim API (OpenStreetMap)
   - エンドポイント: `https://nominatim.openstreetmap.org/search?format=json&q={検索クエリ}&accept-language=ja&limit=5`
   - 制約対策: ユーザーの入力から500ms待って検索を実行するデバウンス（Debounce）処理を実装し、連続リクエストを防止すること。
3. **過去気象データ取得**: Open-Meteo Historical Weather API
   - エンドポイント: `https://archive-api.open-meteo.com/v1/archive`
   - パラメータ: `latitude`, `longitude`, `start_date`, `end_date`, `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_sum,wind_speed_10m_max`, `timezone=Asia%2FTokyo`
   - **重要（通信最適化）**: 年ごとにAPIを分割呼び出しするとレート制限や遅延の原因になるため、`start_date`（N年前の1月1日）から `end_date`（昨日の日付 ※Historical APIの仕様上、直近数日分が欠損する場合は取得可能な最新日）までを**1回のAPIリクエストで一括取得**し、JavaScript側で「指定された月日（MM-DD）」および「直近7日間」のデータを抽出・集計すること。
4. **リアルタイム予報データ取得（ターゲット日が今日から14日以内の場合のみ併用）**: Open-Meteo Forecast API
   - エンドポイント: `https://api.open-meteo.com/v1/forecast`
   - パラメータ: `latitude`, `longitude`, `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_sum,wind_speed_10m_max`, `timezone=Asia%2FTokyo`, `forecast_days=14`

# 2. ユーザー入力インターフェース（UI要件）
スマートフォンでも操作しやすいカード型レイアウトにしてください。

1. **場所の入力（テキストボックス＋サジェスト）**:
   - テキスト入力に応じてNominatim APIから候補を取得し、ドロップダウンでサジェスト表示する。選択すると緯度・経度がセットされる。
   - **クイックタグ機能**: 入力欄のすぐ下に、ワンタップで場所をセットできる定番スポットのチップ（ボタン）を配置する。
     - 初期プリセット例（緯度・経度をハードコードして即座にセット可能にする）：
       - 東京ディズニーランド (`lat: 35.6329, lon: 139.8804`)
       - 東京駅 (`lat: 35.6812, lon: 139.7671`)
       - 横浜 (`lat: 35.4437, lon: 139.6380`)
       - 札幌 (`lat: 43.0618, lon: 141.3545`)
       - 大阪・USJ (`lat: 34.6654, lon: 135.4323`)
       - 那覇 (`lat: 26.2124, lon: 127.6809`)
2. **知りたい日付（日付ピッカー）**:
   - デフォルトは「明日」の日付をセット。任意の年月日を選択可能にする。
3. **集計期間（セグメントボタン または ラジオボタン）**:
   - 「過去5年」「過去10年（デフォルト）」「過去20年」から選択可能にする。
4. **検索・予測実行ボタン**:
   - 通信中はローディングスピナーを表示し、多重クリックを防止する。

# 3. 予測・集計ロジック仕様

### ① 晴天率（お出かけ日和率）の算出
- 過去N年分の「同じ月日（MM-DD）」のデータを抽出する。
- **定義**: WMO `weather_code` が `0, 1, 2, 3`（快晴、晴れ、一部曇り、曇り）かつ、降水量が1.0mm未満だった日を「晴れ・曇り（雨雪なし）」と判定し、N年中の割合（%）を「晴天率（雨雪が降らなかった確率）」として算出する。

### ② 「統計 × 直近気象トレンド」のハイブリッド気温予測
1. **ベース統計値**: 過去N年分の「指定月日（MM-DD）」における最高気温の平均値（`Base_Max`）と最低気温の平均値（`Base_Min`）を算出。
2. **直近トレンド（平年差）の算出**:
   - 過去データ内の最新7日間（例：昨日までの7日間）の実測平均気温と、過去N年の同じ7日間の平均気温を比較し、差分（`Trend_Diff`）を算出する。
3. **ハイブリッド予測値**:
   - `予想最高気温 = Base_Max + (Trend_Diff * 0.3)` （※統計70% : 直近トレンド30%の重み付けで補正）
   - `予想最低気温 = Base_Min + (Trend_Diff * 0.3)`
   - 画面には予測値とともに「（過去平均比 +X.X℃）」のように直近トレンドの影響度もバッジ等で小さく表示する。

### ③ 14日以内の比較表示
- ユーザーが指定した日付が「今日〜14日後」の範囲内である場合、Forecast APIから該当日のリアルタイム予報も取得し、**「過去データからの統計予測」と「現在の最新天気予報」の2つのカードを並べて比較表示**する。

### ④ 服装目安の自動判定
算出された「予想最高気温」をベースに以下のテキストとアイコンを表示する：
- **25℃以上**: 半袖（Tシャツ・ポロシャツなど夏物の装い）
- **20〜24℃**: 長袖シャツ・薄手の羽織（快適に過ごせる服装）
- **15〜19℃**: カーディガン・スウェット（少し肌寒いため重ね着がおすすめ）
- **10〜14℃**: ジャケット・トレンチコート（春・秋物のアウターが必要）
- **9℃以下**: 冬物コート・ダウン（しっかりとした防寒対策が必要）
- **追加条件**: 「予想最高気温 − 予想最低気温」が **10℃以上** ある場合は、『⚠️ 朝晩の寒暖差に注意（日較差 X.X℃）。脱ぎ着しやすい服装がおすすめです』というアラートタグを併記する。

### ⑤ 気象データ上の注意点（自動アラート生成）
過去N年分の同日データを分析し、該当するものがあれば注意点リストとして表示する：
- **大雨リスク**: 降水量が `10mm以上` だった年がある場合 → 「過去N年のうちX回、10mm以上の強い雨が降っています」
- **強風リスク**: 最大風速（`wind_speed_10m_max`）の平均が `7m/s以上` または `10m/s以上` の年が複数ある場合 → 「風が強い傾向があります（過去平均 X.Xm/s）。海沿いやテーマパーク等では防風対策に注意してください」
- **極端な気温**: 過去N年の中で最高気温30℃以上（真夏日）・35℃以上（猛暑日）、または最低気温0℃未満（冬日）があった場合、その回数を注意喚起として表示する。

# 4. 出力画面の構成
結果が見やすく、ワクワクするようなダッシュボード風のデザインにしてください。
1. **サマリーヘッダー**: 選択した場所名、対象日付、集計年数
2. **メイン予測カード**:
   - 晴天率（大きなパーセンテージ表示とプログレスバーまたは円グラフ表現）
   - 予想最高気温（赤系）・予想最低気温（青系）と、過去平均との差分
   - （※14日以内の場合は、隣に「現在のリアル天気予報」カードを並置）
3. **服装アドバイス＆注意点カード**:
   - 服装目安と寒暖差アラート
   - 気象データ上の注意点リスト（アイコン付き）
4. **過去N年分の同日データ履歴一覧（テーブルまたはカードリスト）**:
   - 年ごと（例：2025年、2024年…）の「天気アイコン・天気名」「最高/最低気温」「降水量」「最大風速」を振り返れる一覧表を表示する。
