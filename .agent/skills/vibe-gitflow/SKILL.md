# Vibe Coding Git Flow ルール

コードの変更や新機能の実装を行う際は、必ず以下のGitワークフローを遵守してください。

## 1. ブランチ戦略（軽量Git Flow）
- `main` ブランチは常に「エラーなく動作する安定版」として保つこと。
- 新しい機能や修正に着手する際は、作業前に必ず `feature/機能名` または `fix/修正内容` ブランチを切ってから作業を開始すること。
  - 例: `git checkout -b feature/open-meteo-integration`
  - 例: `git checkout -b feature/clothing-advice-ui`

## 2. コミットの粒度（マイクロコミット）
- 複数の機能を一度にまとめてコミットしないこと。
- 「1つの機能が動いた」「1つのUIパーツが整った」段階で、こまめにコミット（セーブポイント作成）を行うこと。
- コミットメッセージは Conventional Commits 形式（日本語可）で記述すること：
  - `feat: 〇〇機能を追加`
  - `fix: 〇〇の計算エラーを修正`
  - `style: スマホ表示時のカード余白を調整`

## 3. マージとクリーンアップ
- 実装後、コンソールエラーが出ていないことを確認してから `main` ブランチへマージすること。
- 変更が大きくなりすぎて動かなくなった場合は、無理にパッチを当て続けず `git reset` や `git checkout` で直前の正常なコミットに潔く戻すこと。
