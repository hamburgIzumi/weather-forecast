# 堅牢なフロントエンド・API実装ルール

外部APIの呼び出しやデータ集計・画面描画を行う際は、必ず以下の防御的プログラミングを適用してください。

## 1. 外部APIのレート制限・通信エラー対策
- テキスト入力に伴うAPI検索（ジオコーディング等）には、必ず **500ms以上のDebounce（デバウンス）処理** を入れること。
- `fetch` 処理には必ず `try / catch` を実装し、通信エラーやレート制限（HTTP 429等）が発生した際は、画面が白紙にならないようユーザーに分かりやすいエラートーストや再試行メッセージを表示すること。
- 実行ボタンにはローディング状態（スピナー表示＋`disabled`属性）を設け、連打による多重リクエストを防止すること。

## 2. データの欠損値（null / undefined）ガード
- 過去の気象データや外部JSONを集計する際、配列内に `null` や `undefined` が含まれている前提でフィルタリング（`filter(v => v !== null && !Number.isNaN(v))`）を行ってから平均値や確率を算出すること。
- 画面上に `NaN` や `undefined` という文字列が直接表示されることを絶対に防ぐこと（値がない場合は `--` と表示する）。

## 3. モバイルファーストUI（Tailwind CSS）
- すべてのカード、テーブル、グラフはスマートフォン画面（幅375px〜）で横スクロールによるレイアウト崩れが起きないよう、`overflow-x-auto` やグリッドの折り返し（`grid-cols-1 md:grid-cols-2`）を徹底すること。
- タップ要素（クイックタグやボタン）はスマホで押しやすいサイズ（最小高さ 40px 以上、適切な gap）を確保すること。
